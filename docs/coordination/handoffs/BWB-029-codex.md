# Handoff: independent review of BWB-029 (scaffold the GPL-compatible Blixis PHP theme)

READ-ONLY, offline. Branch `feat/29-theme-scaffold`. Read: `docs/architecture/THEME.md`, ADR 0002 (theme architecture), ADR 0001 (floors), ADR 0008/0009 (GPL, distribution), `docs/architecture/WORDPRESS.md` (theme responsibilities, security), `docs/engineering/ACCESSIBILITY-BASELINE.md`, then `wordpress/theme/**` (style.css, functions.php, src/Compat.php, src/Setup.php, header.php, footer.php, templates and template-parts, readme.txt, tests), `docker/compose.packages.yml`, `tooling/wp-env/wp-env.mjs` (package mounts, theme activation, new smoke checks), `tooling/docker.test.mjs`, `composer.json`/`phpunit.xml.dist` changes, `docker/compose.yml` (WP_DEBUG_LOG).

Questions:
1. WordPress theme correctness and requirements: required files and headers (WP.org theme review basics: style.css header fields, license text, `Tested up to`, tags, text domain, readme.txt, `screenshot.png` missing), template hierarchy completeness for a classic theme (home/front-page/page/single/archive/search/404/comments/attachment), use of `wp_body_open`, `wp_head`, `wp_footer`, `language_attributes`, escaping and i18n of every output, `comments.php` correctness (`the_comments_navigation`, `comment_form`, `get_comments_number` casts), `load_theme_textdomain`, `$content_width` handling, `register_nav_menus`, `html5` support list, `wp_enqueue_style` handle/version, `Requires PHP: 8.2` with `declare(strict_types=1)` in a theme that WordPress loads with `include`/`require`.
2. Accessibility baseline: skip link behaviour (`screen-reader-text`, `.skip-link:focus`), `main` with `tabindex="-1"`, landmarks (header/nav/main/footer, `aria-label` on nav), headings (`h1` once per page: check `content.php` on archives, `page-title` in archive/search/404, singular pages), focus visibility, reduced motion, link purpose, `get_search_form()` labels; what must be fixed now versus left to BWB-038.
3. Compat contract: `Compat::from_value` (regex, bounds, the `string|false|null` signature), `declared()` using `get_file_data`, `active()` parent fallback for child themes (a child with its own header vs without; a child theme that declares a *different* number than the parent), the header name and format versus ADR 0002 open question. Is the parser rule safe to copy into the plugin (BWB-047)?
4. Dev/CI integration: bind mount of the theme into both containers (read-only), activation in `install()`, idempotence of `wp theme activate`, smoke checks (do they pass for the right reasons; is checking `debug.log` for `/themes/blixis/` robust; does turning `WP_DEBUG_LOG` on create any risk or flakiness; Windows paths), `docker.test.mjs` assertions, behaviour when the compose.packages file is absent, CI matrix (WordPress 7.0/PHP 8.2 and 7.1/PHP 8.5): anything that could fail on PHP 8.5 (deprecations in templates or tests).
5. Tooling: PHPStan `--memory-limit=1G`, PHPUnit suite `theme` that loads theme files outside WordPress with a fake `ABSPATH`, PHPCS exclusions, packaging (`pnpm build` includes `src/`, excludes `tests/`; header version equals package.json), the `defined( 'ABSPATH' ) || exit;` guards, GPL headers, secrets.
6. Anything in this scaffold that will be painful to change later (file names, hooks, handles, text domain, `Blixis\Theme` namespace, the `src/` directory name) given BWB-030 to BWB-038 and the plugin (BWB-039+).

Output: Blocker/Major/Minor with file + fix wording; agreements; what you could not verify.
