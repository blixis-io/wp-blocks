It does not include a competing dark+mobile+hover rule. Add one compact case now to pin that interaction. **Minor — document the limits of the mutation claim.** [BREAKPOINTS-AND-STATES.md](docs/architecture/BREAKPOINTS-AND-STATES.md:60) reports three hand mutations, but provides no mutation diff, command or failure output to reproduce them. ## Agreements and scope

The [expected-value formula](tests/fixtures/src/style-matrix.test.ts:37) is correct under ADR 0005: for dark mobile, combined → dark → mobile → base; elsewhere, skip rules that do not match; active hover wins within element origin. The [group C table](tests/fixtures/src/style-matrix.test.ts:87) is also correct. Its expectations are written separately from the library resolver, though the test uses the compiler’s class-name metadata to select the element being evaluated.

The 16 combinations are exercised for both modes and all three viewport categories, with normal and hover contexts in Group S. At 641px the test is **tablet**, not mobile; 640px is mobile. Explicit light against system dark and explicit dark against system light are tested; `auto` and absent theme follow either system preference. A mismatch between `auto` and its effective system mode is not a separate valid context. Light-specific rules and token values are outside this matrix and have other fixtures. Browser computed styles, JavaScript-disabled behavior and PHP execution remain separate work under the ADR’s test strategy.

The [7,155-byte golden](tests/fixtures/compile/compile-style-matrix.golden.css:1) is a reasonable single-file contract for 36 elements. Its declared layer order, merged and sorted selectors, and explicit/auto media nesting match the ADR and the fixture. The generator’s [Python `hashlib` names](tests/fixtures/style-matrix.generate.py:18) independently check the TypeScript hash result; the golden CSS itself is still compiler-produced, with separate hand-derived stylesheet checks in [compile.contract.test.ts](tests/fixtures/src/compile.contract.test.ts:46).

The [testing export](packages/style-engine/package.json:12) is acceptable for the fixture package. I found no production import of it. The export makes an accidental future production import possible, so a bundle check should guard that boundary when the editor build exists. Current sorting uses code-unit comparisons and numeric ranks, with no `localeCompare`; generated selector names are ASCII. The determinism test reverses document keys and root order, but does not reorder class or token inputs or directly probe Map insertion order. Those are useful broader compiler tests; changing class-list order itself is intentionally semantic.
