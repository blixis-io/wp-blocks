## BWB-011 review

**Blocker — Plus/Pro boundary conflicts with ADR 0009.** [boundaries.json](tooling/boundaries.json:15) allows both add-ons to depend on `core`, `element-registry`, `capabilities`, and `design-tokens`. Those are Builder workspace packages, while [ADR 0009](architecture/adrs/0009-distribution-and-package-boundaries.md:25) says paid distributions contain no copy of Builder code and use only its public, versioned extension API. Remove runtime edges to Builder internals; define a public API/types contract if needed, and verify add-on artifacts contain no bundled Builder code. If these dependencies are intended solely for types, say so and enforce type-only imports and build externalization.

**Major — dependency aliases bypass the checker.** [check-boundaries.mjs](tooling/check-boundaries.mjs:33) checks dependency keys but barely examines values. For example, an innocuous key can use `npm:gsap@…` or a `workspace:` alias targeting a disallowed internal package. Resolve alias targets before applying the denylist and graph rules; test both forms. `workspace:^` on a correctly named dependency is accepted as intended.

**Major — workspace discovery does not match pnpm’s source of truth.** [check-boundaries.mjs](tooling/check-boundaries.mjs:46) hardcodes four directories, does not check `tooling` or compare [pnpm-workspace.yaml](pnpm-workspace.yaml:1), and skips undeclared directories without `package.json`. A configured package outside the globs can pass despite not being a pnpm workspace; `reserved` also exempts `apps/docs` even if it gains a manifest. Discover workspace manifests from the actual globs, compare them bidirectionally with `boundaries.json`, and reject unmanifested package directories where the layout expects packages.

**Major — the “global” dependency ban excludes the root.** The root [package.json](package.json:1) is never checked, so it could declare GSAP despite [ADR 0008](architecture/adrs/0008-dependency-licensing-and-gsap.md:16) banning it throughout the repository. Include root dependencies and lockfile resolutions in the ban. This also catches aliases and transitive resolutions.

**Minor — manifest rules need a few negative tests.** The existing tests would fail if the checker were gutted: they assert specific violations, not just a successful exit. [check-boundaries.test.mjs](tooling/check-boundaries.test.mjs:31) lacks failing cases for `devDependencies`, `peerDependencies`, `optionalDependencies`, unknown internal names, unknown `allow` targets, invalid JSON, duplicate configured names, alias targets, a configured path outside workspace globs, and root dependencies. Add focused cases for the consequential gaps. JSON `exports` and `imports` self-references are not inherently violations; external or cross-package targets there need the later source/import check promised by [ADR 0010](architecture/adrs/0010-monorepo-layout-and-package-boundaries.md:41).

**Minor — Node range overstates support.** [ADR 0001](architecture/adrs/0001-supported-environments.md:20) and `.nvmrc` select Node 24, but root `engines.node: ">=24"` also accepts newer releases before they enter the stated CI matrix. Use a bounded range for the supported major and widen it when Node 26 joins CI. The ADR amendment itself is internally consistent.

The remaining graph is a reasonable initial separation. `canvas-bridge → element-registry` and `style-engine → capabilities` are not established needs by the current contracts; add either only when a concrete implementation needs it. ADR 0005’s TS/PHP fixture parity does not require a PHP runtime dependency on the TS package. The plugin’s editor edge is compatible with NFR-001 **provided** build and enqueue checks later prove the editor bundle is absent from public pages; this manifest checker cannot prove that. The committed lockfile, exact pnpm version, workspace globs, `.nvmrc`, and `.gitignore` are coherent. With no third-party packages yet, `onlyBuiltDependencies` and `minimumReleaseAge` are sensible to decide before adding them, rather than blockers now.

**Verification limits:** `node tooling/check-boundaries.mjs` passed for 15 declared packages. `pnpm` commands attempted a write and were denied by this read-only environment. Direct `node --test` passed the real-tree test; nine fixture tests could not create temporary directories (`EPERM`), so their runtime assertions remain unverified here. I did not verify installation, build outputs, public-page enqueues, or CI offline.
